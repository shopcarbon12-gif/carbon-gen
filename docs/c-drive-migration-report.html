What this report covers (and does not)

In scope here: Moving Cursor, Codex, and .cursor data off C:\ onto D:\, user env vars, desktop shortcut, and running the cleanup script after Cursor is fully closed.
Out of scope here: VirtualBox, Ubuntu, Docker Engine in the VM, git pull, Coolify, production deploys, or D:\archive-pre-linux-verify\ project zips — those live in docs/virtualbox-linux-cursor-flutter-android-guide.html and docs/AGENT_HANDOFF_VIRTUALBOX_LINUX.md.

Automated backup: D:\backup c, zips, optional Ubuntu scp

Close Cursor completely before running (tray + Task Manager). Do not run from Cursor’s integrated terminal. Use an external PowerShell window. Optional: -StopCursorProcesses on the backup script to kill Cursor processes first.

scripts\backup-c-to-d-and-ubuntu.ps1 does the following end-to-end on Windows:

  • Creates D:\backup c\ with one subfolder per source path (e.g. AppData-Roaming-Cursor, UserProfile-dot-cursor, AppData-Local-Cursor).
  • Robocopy copies each tree from C:\ into the matching subfolder.
  • Builds a zip per folder under D:\backup c\archives\ (uses Windows tar.exe).
  • Writes D:\backup c\BACKUP_REPORT_<timestamp>.txt with C: free space before/after and approximate GB backed (sizes measured on D: after copy).
  • If you pass -SshHost and -SshUser, uploads each zip with scp to ~/backup-from-windows-c/archives/ on the VM. Use -SshPort 22 with your bridged IP, or -SshPort 2222 if the host forwards 2222 → guest 22 (VirtualBox NAT). Install OpenSSH Client on Windows if scp is missing. SSH keys or interactive auth must work; BatchMode requires keys.

By default the script does not delete anything on C:\. To remove sources after a good copy + zip, add -DeleteSourcesAfterCopy (use only when you trust the backup).

Dry run:

powershell -ExecutionPolicy Bypass -File "d:\Projects\My project\carbon-gen\scripts\backup-c-to-d-and-ubuntu.ps1" -WhatIf

Example (bridged VM, port 22):

powershell -ExecutionPolicy Bypass -File "d:\Projects\My project\carbon-gen\scripts\backup-c-to-d-and-ubuntu.ps1" `
  -StopCursorProcesses `
  -SshHost "192.168.x.x" -SshUser "eliorp1" -SshPort 22

Example (NAT forward localhost:2222 → guest:22):

powershell -ExecutionPolicy Bypass -File "d:\Projects\My project\carbon-gen\scripts\backup-c-to-d-and-ubuntu.ps1" `
  -StopCursorProcesses `
  -SshHost "127.0.0.1" -SshUser "eliorp1" -SshPort 2222

Skip Ubuntu upload: add -SkipScp.

The AI/agent in Cursor cannot run this safely for you while this IDE holds locks on the same files; you (or another agent in a non-Cursor shell) must run it.

Pending — finish C:\ cleanup

~13.5 GB may still sit on C:\ under AppData\Roaming\Cursor and C:\Users\Elior\.cursor while those folders are locked by a running Cursor process.
  1. Quit Cursor completely (check Task Manager for stray processes).
  2. Run the cleanup script (command above) from an elevated or normal PowerShell as required by the script.
  3. Open Cursor only via Cursor (D-Drive) — do not use an old shortcut that still points at default C:\ data.
  4. Optionally verify free space on C:\ and that the two paths above are gone or empty.
