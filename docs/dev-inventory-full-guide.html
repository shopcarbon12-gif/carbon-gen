Overview

The goal is a repeatable picture of where dev tools, repos, caches, and backups live, plus a git triage sheet, before you move or mirror data to Ubuntu. Scripted layers L1, L2, L3, L5 live in scripts/dev-disk-inventory.ps1. L4 is a separate manual full-drive pass so nothing large is missed by heuristics.

LayerWhat it isHow
L1 Canonical dev paths (Cursor, VS Code, npm/gradle/Android, Flutter, live repos, backup roots, gitconfig, .ssh meta, WSL ext4.vhdx list). Script
L2 Every top-level folder on D:\ with recursive size; dev heuristics; optional git discovery and shallow zip listing under large/likely-dev trees. Script
L3 User profile subdirs (except AppData whole-tree duplicate) and targeted ProgramData dev-related subtrees. Script
L4 Full visualization of everything large on C: and D: (treemap / export). Manual (WinDirStat or WizTree)
L5 Per .git work tree: remote, branch, dirty state, untracked bucket, unpushed hints. Script (unless -SkipGitTriage)
Large backup trees: By default, backup_mirror (D:\backup c) and backup_tree (D:\Projects\carbon-gen-backups-outside) skip full recursive byte counting in L1/L2 so runs finish in reasonable time. CSV rows show SizeGB 0 with a note; use L4 or run with -FullSizeBackupRoots for a slow, full deep size.

Order of operations

L1 (script) → L2 (script) → L3 (script) → extra-scan-roots.txt (script) → write dev-inventory-*.csv → L5 git triage (script) → git-triage-*.csv → Done → then L4 manual (C: + D:) → save exports to inventory\ → triage spreadsheets → backups / mirror D:\backup c to Ubuntu

PowerShell script: run and parameters

Script path (repo): scripts\dev-disk-inventory.ps1

Typical run (from repo root or with full path):

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "d:\Projects\My project\carbon-gen\scripts\dev-disk-inventory.ps1"

Dry run (no writes, lists intent):

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts\dev-disk-inventory.ps1" -WhatIf

No Outlook phase mail (L1/L2/L3/L5/Complete):

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts\dev-disk-inventory.ps1" -SkipOutlookPhaseNotify

Skip git triage (faster if you only want the master CSV):

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts\dev-disk-inventory.ps1" -SkipGitTriage

Full recursive sizing for huge backup roots in L1/L2 (can take many hours):

powershell.exe -NoProfile -ExecutionPolicy Bypass -File "scripts\dev-disk-inventory.ps1" -FullSizeBackupRoots

Parameters (reference)

ParameterRole
-BackupRootDefault D:\backup c. Inventory CSVs go under <BackupRoot>\inventory\.
-WhatIfPreview only; exits before creating rows or CSVs.
-SkipGitTriageNo git-triage-*.csv.
-SkipOutlookPhaseNotifyDisable phase emails via Outlook.
-OutlookNotifyTo / -OutlookSendAsSmtpRecipient and send-as account (SMTP address) for Outlook.
-FullSizeBackupRootsFull recurse for backup mirror/tree in L1 and matching D:\ folders in L2.
-GitTriageMaxReposCap repos triaged (default 200).
-DDeepScanMinSizeGbL2 threshold for deep zip/git crawl (default 2 GB).
-DeepScanMaxZipDepthMax depth for zip discovery under L2 (default 8).
L1/L2 console progress: The script logs each path scanned and elapsed time so a long run does not look “stuck.”

Outputs and extra roots

ArtifactLocation

Git triage CSVD:\backup c\inventory\git-triage-<timestamp>.csv

After L4, if WizTree shows large folders not in the master CSV, add their paths to extra-scan-roots.txt and re-run the script.

Monitoring a long run

  • Log file (optional wrapper): If you use tmp\dev-inventory-child.ps1, output is appended to tmp\dev-inventory-run.log under the repo.
  • Done marker: The child wrapper writes tmp\dev-inventory-done.flag when the script exits.
  • Status helper: tmp\check-inventory-run.ps1 reports running PIDs, done flag, log tail, and recent CSVs under D:\backup c\inventory\.
  • Outlook: With phase notify on, you get an email after L1, L2, L3, extra roots, L5, and Complete.

L4 — WinDirStat / WizTree (mandatory full-drive maps)

L4 is not automated by the PowerShell script. Use a disk visualization tool on C: and D: so odd paths (renamed folders, games, Dropbox, spillover from C:\) are visible.

Save everything under: D:\backup c\inventory\
Include these when you mirror D:\backup c to Ubuntu (~/backup-from-windows-c/) so an agent can confirm L4 exists.

Suggested filenames

  • windirstat-C-drive.png / windirstat-D-drive.png (or saved report if the tool supports it)
  • wiztree-C-drive.csv / wiztree-D-drive.csv

WinDirStat

  1. Install from windirstat.net if needed.
  2. Optional: run as Administrator for fewer “access denied” gaps.
  3. Select drive C: → OK → wait until the scan finishes.
  4. File → Save report and/or screenshot the treemap and top directories → save into D:\backup c\inventory\.
  5. Repeat for D:.

WizTree

  1. Install from antibody-software.com/wiztree (or Microsoft Store).
  2. Select C: → Scan → File → Export CSV (or screenshot top folders).
  3. Save into D:\backup c\inventory\ (e.g. wiztree-C-drive.csv).
  4. Repeat for D:.
Why both drives: C: catches profile and Program Files spillover; D: catches large trees the L2 heuristics might not label as “dev.”

Triage, dedupe, and actions

After the script and L4, use a spreadsheet (Excel / LibreOffice) to merge CSVs and decide what to keep, archive, or push.

Inputs

FilePurpose
dev-inventory-<ts>.csvMaster rows (L1–L3, zip rows, profile-related rows).
git-triage-<ts>.csvPer repo: remote, branch, dirty, UntrackedBucket, unpushed hints; SuggestedAction left empty for you.
extra-scan-roots.txtYour custom paths for the next script run.
L4 exportsEvidence for “what is huge” on C: and D:.

Columns to add or fill manually

ColumnYou fill
SuggestedProjecte.g. carbon-gen, carbon-wms, general, unknown.
DuplicateOfCanonical path if this row is a duplicate backup.
Actione.g. KEEP_CANONICAL, ARCHIVE_THEN_DELETE, PUSH_FIRST, COMMIT_THEN_PUSH, INSPECT, CACHE_OK_DELETE_AFTER_BACKUP.
ReviewedY when decided.

Dedupe rules (short)

  1. Same Remote in git triage and similar folder names → likely duplicate repo; keep one live tree (often under D:\Projects\My project\...), mark others DuplicateOf that path.
  2. Same-date zips with same project → keep newest or smallest complete copy after a quick content check.
  3. Caches (npm-cache, .gradle, disposable node_modules) → CACHE_OK_DELETE_AFTER_BACKUP only after git is clean/pushed or redundant.

Commit decision matrix

SituationTypical Action
Git clean and pushedKEEP or ARCHIVE_THEN_DELETE if duplicate.
Git dirty or unpushedCOMMIT_THEN_PUSH or PUSH_FIRST before any delete.
Not git (zip / copy)INSPECT or ARCHIVE_THEN_DELETE when redundant.
Cursor profile on C:Back up with scripts\backup-c-to-d-and-ubuntu.ps1 first; do not delete before Ubuntu verify.

Consolidating under D:\backup c\

When moving (not copy-delete) duplicates into the backup tree, use a consistent pattern, for example project-repos\archives\carbon-gen-<date>-from-<short-path>.zip. Keep Cursor archives under archives\ per your backup scripts. Do not delete canonical D:\Projects\My project\... repos for migration; remove extras only after backups and your explicit approval.

Which agent owns what

  • CarbonGen — confirm remotes and paths for Next.js / carbon-gen trees when SuggestedProject is ambiguous.
  • Carbon Warehouse — confirm Flutter / WMS trees when ambiguous.
  • General Windows — inventory scripts, D:\backup c\inventory\ layout, CSV regeneration.

See cursor-three-agent-prompts.md for copy-paste prompts.

After inventory — backups and Ubuntu

When triage is good enough, run your backup scripts (e.g. scripts\backup-c-to-d-and-ubuntu.ps1, scripts\backup-projects-to-d.ps1) per migration-ubuntu-master-plan.md, then mirror the full D:\backup c tree (including inventory\ and L4 files) to Ubuntu.
