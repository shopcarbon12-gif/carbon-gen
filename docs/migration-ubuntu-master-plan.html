Cursor: global vs project settings

  • Global: %APPDATA%\Cursor\User\settings.json — machine-wide (e.g. font size, theme). Yours is currently minimal.
  • Per repo: .vscode/settings.json for workspace excludes, terminal profile, ESLint roots, extension workspace config. Present today: carbon-gen, carbon-warehouse-management.
  • Cursor rules: .cursor/rules/*.mdc — active sets in carbon-gen and carbon-warehouse-management.

Rule of thumb: stack-specific → repo .vscode / .cursor; personal preference everywhere → global settings.json.

Cursor backups = transcripts + profile

  • %APPDATA%\Cursor and %USERPROFILE%\.cursor hold settings, extensions, workspace storage, AI/chat-style history, and related data.
  • Goal: Preserve what you need so transcripts are not lost. Each fresh backup run copies/zips the current profile from disk.
  • Git remains source of truth for code; project backups are separate.
  • Separate zips for project trees vs Cursor profile zips. backup-projects-to-d.ps1 defaults to carbon-gen + CarbonWMS; add paths for any extra artifacts you keep under My project.
  • Files that Cursor/other tools write inside the profile trees stay inside the Cursor backup — no need to split manually.

Phase 0 — Pre-flight (before backup)

For every git repo in the inventory: git status, unpushed vs origin (repos with no remote cannot push until you add one). When you request it: commit, push, and production deploy (npm run deploy:coolify for carbon-gen, warehouse equivalent for CarbonWMS). Side branches / local-only repos may have no deploy. List non-git folders for manual copy. Secrets never committed; scan untracked files before zipping.

Phase 1 — Fresh backups on Windows

1A — Cursor profile

scripts/backup-c-to-d-and-ubuntu.ps1 — Cursor fully quit. Refreshes D:\backup c\ folders and zips under D:\backup c\archives\.

1B — Projects (separate zips)

scripts/backup-projects-to-d.ps1 — defaults to carbon-gen + carbon-warehouse-management. Default output D:\backup c\project-repos\ (-BackupRoot to override). Excludes node_modules, .next, etc. unless -FullTree. To archive all of D:\Projects\My project (and carbon-gen-backups-outside), extend the script or run an additional full-folder copy into D:\backup c\ or straight to Ubuntu.

Phase 2 — Ubuntu: full D:\backup c mirror

Replace or archive old ~/backup-from-windows-c, then copy the entire D:\backup c tree to /home/eliorp1/backup-from-windows-c/ (rsync, scp -r, or shared folder). Quote paths for the space in backup c.

Again: mirror = duplicate files by copying/syncing — not a junction or symlink.

Phase 3 — C: vs D:

Projects on D: are not required to be deleted for migration. Optional: -DeleteSourcesAfterCopy on the Cursor backup script removes only Cursor profile paths on C:, not D:\Projects\....

Phase 4 — localhost:3000 and :3040

Working trees under /home/eliorp1/dev/carbon-gen and .../carbon-warehouse-management (plus other inventory dirs as /home/eliorp1/dev/<name> when needed), npm install, env files, Docker per README. Resolve Postgres 5432 clash if both stacks use it. Bind 0.0.0.0 if you hit dev servers from the Windows host via port forwarding. Verify real app behavior, not only that ports listen.

Phase 5 — One Cursor on Ubuntu

After stable verification: uninstall Cursor on Windows. No junctions, no mirrors. Single Cursor on Ubuntu for dev/build/design.
