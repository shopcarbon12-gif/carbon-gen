Cursor backups = transcripts + profile

  • %APPDATA%\Cursor and %USERPROFILE%\.cursor hold settings, extensions, workspace storage, AI/chat-style history, and related data.
  • Goal: Preserve what you need so transcripts are not lost. Each fresh backup run copies/zips the current profile from disk.
  • Git remains source of truth for code; project backups are separate.
  • Separate zips for the two repos vs the two Cursor profile zips. Files that Cursor/other tools write inside the profile trees stay inside the Cursor backup — no need to split manually.

After Ubuntu has backups: prompt for AI agents

Once D:\backup c is mirrored to /home/eliorp1/backup-from-windows-c/, paste this into Cursor on Ubuntu, Claude Code, or other agents:

Windows backups are mirrored on this machine at:
  /home/eliorp1/backup-from-windows-c/

Use it as the canonical offline reference for:

  - Project zip/trees if present: backup-from-windows-c/project-repos/ (and archives under it) or any project zips under archives/projects/

Do not delete or rewrite files there unless I explicitly ask. For day-to-day work, prefer /home/eliorp1/dev/carbon-gen and /home/eliorp1/dev/carbon-warehouse-management after restore/clone.

Adjust subpaths if your sync layout differs.

Phase 0 — Pre-flight (before backup)

In both repos: git status, unpushed commits vs origin. When you request it: commit, push, and npm run deploy:coolify (or warehouse equivalent) so web/apps match origin and production is current. Flutter/other roots if applicable. Secrets (.env.local) never committed.

Phase 1 — Fresh backups on Windows

1A — Cursor profile

scripts/backup-c-to-d-and-ubuntu.ps1 — Cursor fully quit. Refreshes D:\backup c\ folders and zips under D:\backup c\archives\.

1B — Projects (separate zips)

scripts/backup-projects-to-d.ps1 — defaults to the two Windows paths. Default output root D:\backup c\project-repos\ (override with -BackupRoot). Excludes node_modules, .next, etc. unless -FullTree.

Phase 2 — Ubuntu: full D:\backup c mirror

Replace or archive old ~/backup-from-windows-c, then copy the entire D:\backup c tree to /home/eliorp1/backup-from-windows-c/ (rsync, scp -r, or shared folder). Quote paths for the space in backup c.

Phase 3 — C: vs D:

Projects on D: are not required to be deleted for migration. Optional: -DeleteSourcesAfterCopy on the Cursor backup script removes only Cursor profile paths on C:, not D:\Projects\....

Phase 4 — localhost:3000 and :3040

Working trees under /home/eliorp1/dev/..., npm install, env files, Docker per README. Resolve Postgres 5432 clash if both stacks use it. Bind 0.0.0.0 if you hit dev servers from the Windows host via port forwarding. Verify real app behavior, not only that ports listen.

Phase 5 — One Cursor on Ubuntu

After stable verification: uninstall Cursor on Windows. No junctions, no mirrors. Single Cursor on Ubuntu for dev/build/design.

Personal end state (your statement)

After Ubuntu is 100% trusted, you may permanently remove essentially all dev-related files/software from the entire Windows PC, keeping only what you explicitly preserve. This document does not execute that wipe. Ensure git, Coolify, and off-host backups are satisfied first.

Are D:\ / C:\ irrelevant after?

For daily dev: yes — you work under /home/eliorp1/dev/.... Still relevant sometimes: git remotes, Coolify/production, hardcoded paths in docs/scripts, webhooks/tunnels pointing at old Windows localhost.
