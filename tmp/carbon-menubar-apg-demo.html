Carbon storefront — navigation pattern comparison

This page is a local demo only (not your live theme). It shows roughly how your black header could look with two different accessibility approaches. Use Tab to move focus; on the second example, use arrow keys inside the menubar as described in the W3C ARIA Authoring Practices — Menu and Menubar pattern.

Reference: W3C APG — Menu and Menubar Pattern (keyboard table and roles).

Option A — Plain navigation (often enough for a shop)

Top links are normal <a href> inside <nav>. No role="menubar". Mega-menus open on hover/click in the real theme; here it’s just the top row so you see the semantic difference. Many accessibility specialists prefer this for site navigation because it behaves like standard links for keyboard and screen readers.

Option B — APG-style menubar + mega menu (this demo is interactive)

This block follows the menubar / menu / menuitem model from the APG. Parent items open a role="menu" panel; focus moves with arrows inside the bar and inside open menus, Esc closes. Visually it mimics your dark header + white mega panel.

How to choose (plain language)

  • Option A is easier to maintain and matches how most users expect a website header to work (Tab, Enter).
  • Option B is appropriate when you commit to full keyboard behavior from the APG menubar pattern — arrow keys, focus trapping rules, and correct aria-expanded on every dropdown.
  • Putting role="menubar" on a Shopify mega menu without that behavior is what triggers many automated audit warnings.
